# Sahay: AWS Infrastructure & Feature Requirements

If you are rebuilding the Sahay architecture from scratch, here is the complete blueprint of everything you need to implement. This covers the databases, storage, AI integrations, API endpoints, and the multi-agent Step Functions orchestration.

> [!NOTE]
> This guide outlines *what* needs to be built and *how* the components interact, leaving the exact code implementation up to you.

---

## 1. Core Data Storage (Amazon DynamoDB)

You need to provision four DynamoDB tables with `PAY_PER_REQUEST` billing:

1. **CaregiverProfiles** (`sahay-caregiver-profiles`)
   - **Partition Key**: `caregiverId` (String)
   - **Purpose**: Stores the caregiver's details and the Alzheimer's patient's profile (name, dementia stage, emergency contacts, safe home address, daily routine, likes/dislikes).

2. **ConversationLogs** (`sahay-conversation-logs`)
   - **Partition Key**: `conversationId` (String)
   - **Global Secondary Index**: `caregiverId` + `timestamp`
   - **Purpose**: Logs all chat history between the caregiver and the AI, as well as distress incidents from the patient.

3. **DistressScores** (`sahay-distress-scores`)
   - **Partition Key**: `scoreId` (String)
   - **Global Secondary Index**: `caregiverId` + `timestamp`
   - **Purpose**: Logs every distress score (1-10) generated by the AI to build trend graphs (e.g., detecting sundowning).

4. **RouteConfigs** (`sahay-route-configs`)
   - **Partition Key**: `patientId` (String)
   - **Purpose**: Stores geofence coordinates and safe-zone radii for location monitoring.

---

## 2. Object Storage (Amazon S3)

1. **Knowledge Base Docs** (`sahay-kb-docs`)
   - **Purpose**: The data source for Amazon Bedrock Knowledge Bases. You will upload medical guidelines and specific caregiver notes here for the AI to retrieve (RAG).
2. **Audio Storage** (`sahay-audio`)
   - **Purpose**: Temporary storage for 20-second panic audio buffers uploaded from the frontend, and for pre-synthesized AWS Polly audio files. Should have a 1-day auto-delete lifecycle rule.

---

## 3. Alerts & Event Routing

1. **Amazon SNS** (`sahay-alerts`): An SNS topic that caregivers subscribe to via SMS or Email to receive instant emergency alerts.
2. **Amazon EventBridge** (`sahay-events`): A custom EventBus used for asynchronous triggers (e.g., triggering a Lambda when a patient leaves their geofence).

## 4. The AI Agents & AWS Lambda Functions

You will need to build the following Lambda functions (using Node.js 20.x or 24.x). 

### Patient-Facing AI
1. **VoiceCompanionHandler** (`POST /patient/voice`)
   - **Feature**: The real-time conversational brain for the patient. 
   - **Implementation**: Takes the patient's voice transcript, fetches their `patientProfile`, and sends a highly contextual system prompt to a fast LLM (e.g., Groq Llama 3 or Qwen).
   - **Output Requirement**: Must return JSON containing `response` (text to speak), `isDistress` (boolean), `distressScore` (1-10), and `shouldAlertCaregiver` (boolean).
2. **TranscribeHandler** (`POST /patient/transcribe`)
   - **Feature**: STT fallback using Groq Whisper when Deepgram is unavailable.

### Caregiver-Facing AI (Multi-Agent System)
1. **OrchestratorHandler** (`POST /chat/orchestrate`)
   - **Feature**: The entry point for caregiver chat. It takes the caregiver's text and triggers an AWS Step Functions state machine.
2. **TriageAgent** 
   - **Feature**: An AI that analyzes the caregiver's message and classifies it as `ROUTINE` (needs guidance) or `EMERGENCY` (needs escalation).
3. **CareGuidanceAgent**
   - **Feature**: Triggered if triage is `ROUTINE`. Uses Amazon Bedrock Knowledge Bases (RAG) to provide medical advice or routine guidance based on documents in S3.
4. **EscalationAgent**
   - **Feature**: Triggered if triage is `EMERGENCY`. Immediately publishes an alert to the SNS topic to notify emergency services or family members.

### Background & Autonomous Agents
1. **RouteMonitor** (`POST /route/ping`, `GET /route/status`)
   - **Feature**: Receives GPS pings from the patient's phone. Calculates the distance to the safe-zone using the Haversine formula. If the patient breaches the radius, it emits a `RouteAnomalyDetected` event to EventBridge.
2. **CalmingResponseAgent** 
   - **Feature**: Triggered by the EventBridge anomaly event. Uses Amazon Bedrock to generate a personalized calming message ("Protham, you seem lost. Stop walking, I am calling your son"), synthesizes it into speech using AWS Polly, saves it to S3, and alerts the caregiver.
3. **BurnoutChecker**
   - **Feature**: A cron job (EventBridge Schedule) running every 24 hours. It scans the `DistressScores` and `ConversationLogs` tables to detect signs of caregiver burnout. If detected, it sends a supportive nudge via SNS.

---

## 5. Multi-Agent Orchestration (AWS Step Functions)

To tie the Caregiver agents together, build a Step Functions State Machine:
1. **State 1**: Invoke `TriageAgent`.
2. **Choice State**: Look at the output of TriageAgent (`$.autoEscalate`).
3. **Branch A (True)**: Invoke `EscalationAgent`.
4. **Branch B (False)**: Invoke `CareGuidanceAgent`.

---

## 6. Frontend Integration Points

Once your infrastructure is built, your frontend will need to interact with it:
- **API URL**: Connect all fetch calls to the API Gateway URL.
- **Patient Speech**: Use `window.speechSynthesis` to speak the text returned by `VoiceCompanionHandler`.
- **Location Polling**: Use `navigator.geolocation.watchPosition` to continuously `POST /route/ping` to your Route Monitor.
- **Audio Capture**: Use the `MediaRecorder` API to keep a rolling 20-second buffer of audio. When the AI returns `shouldAlertCaregiver: true`, upload this blob to `POST /distress/audio`.

## 7. Frontend Design & UX Requirements

When rebuilding the frontend UI, the visual and behavioral design must strictly follow the aesthetic choices of the current iteration. There is no code here, just the strict UX requirements you need to implement.

### Patient Page (The "Zen" Morphing Orb)
- **Aesthetic**: Deep, dark fullscreen background to minimize sensory overload and eliminate distractions.
- **Typography**: Large, high-contrast, highly legible serif fonts (e.g., `DM Serif Display` or `Syne`) to provide a calming, humanizing feel rather than a robotic tech interface.
- **Visuals**: A central "morphing orb" that fluidly changes shape. It must react to the AI's status: gently pulsing when listening, expanding/animating when speaking, and changing to a warm alert color when high distress is detected.
- **Behavior**: Must be entirely hands-free after the initial browser interaction (the required first click to enable audio playback). The microphone should constantly listen in the background, implementing intelligent wake-word filters (e.g., responding to "Sahay", or detecting cries for help) without requiring button presses.

### Memory Theater Page
- **Concept**: A visual chronological timeline to help ground patients suffering from dementia or severe memory loss.
- **Aesthetic**: A scrolling, timeline-based layout showing the patient's life events, familiar faces, and daily routines.
- **Integration**: The timeline must visually hook into the AI. When the patient is confused about their routine or who a family member is, the Voice Companion should be able to reference the timeline.

### Caregiver Dashboard
- **Aesthetic**: Clean, data-driven, and highly actionable.
- **Features**: Must display a real-time graph of distress scores, live conversation logs, and the patient's current GPS location on a map overlay. Needs clear, un-ignorable UI indicators when an emergency escalation is triggered by the Step Functions backend.
